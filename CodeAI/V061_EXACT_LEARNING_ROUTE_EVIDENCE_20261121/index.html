    v0.61 — CodeAI学習経路の現行正本再照合（提案・監査資料）¶

    対象正本：itakura-hidetoshi/KuuOS canonical main ac5f7db4425e7d377abce8cadee676b4e34341a4、 Git tree f043d43e953cd793122acdb64beaf83ab68e6585。 固定 Lean v4.30.0-rc2、 mathlib 5450b53e5ddc75d46418fabb605edbf36bd0beb6。

    1. 現行ソースの学習経路¶

    歴史原本 docs/CodeAI/README.md は2026-07-18の更新で、 後続の学習・制御経路を網羅しない。後から追加されたLean・Python仕様：

    1. TypedErrorClassificationV0_1： 正確なsource候補＋static preflight finding＋baseline digestを 版・candidate単位で分類。分類は観測であって構造原因の証明ではない。 Leanの実elaborator/linter診断を勝手にstatic taxonomyに写さない。
    2. VerificationGuidedCandidateRepairRegenerationV0_1： 独立検証実行が失敗またはbudget-abortした場合のみ、 完全な受領書・証拠・候補・sourceのdigest連鎖を検証し、 check ID、reason IDs、exit、stderr/stdout digestとbounded excerpt を修復文脈として次候補に渡す。成功した検証は失敗修復に入れない。
    3. BoundedRepairCycleOrchestrationV0_1： 失敗した候補を同じcycleの再選択から外し、 別候補をin-memory isolateへ置いて限定検証。 次cycleは条件付き提案に留まり自動起動しない。
    4. VersionBoundRepairMemoryV0_1： 独立した修復者・検証者・記憶管理者が発行した verified_effective／verified_ineffective／inconclusive を同一commit・source snapshot・候補・typed error・fingerprint・ schema・Lean toolchain・dependency manifest・repair policyの 完全一致で照合。verified_effectiveだけ再利用候補。 Memory自身はread-onlyで永続追記も修復実行もしない。
    5. SubtaskLevelVersionBoundMemoryV0_1（2026-07-21）： localize／diagnose／edit／verify各subtaskに exact source SHA・source-tree digest・temporal holdout corpus・ context pack・verifier ensemble・subtask contract・ predecessor output・dependency slice・toolchain・environment・ memory policyを結び付ける。 verified_usefulの有効で独立検証された履歴のみ policyに従いヒント化。stale/superseded/holdout-derivedは除外。
    6. TrajectoryGroundedSpecialistRouterAdmissionV0_1： exact memory packと部分実行軌跡・測定済み独立証拠を照合し、 formal等の専門処理先を提案する。実dispatchをしない。
    7. EnvironmentCapsuleLivelockEfficiencyGateV0_1： exact toolchain、依存、固定runner環境、観測可能な進捗、 zero-progress/cycles、tool/token/time budgetを検証。 livelock・version差異・自己申告だけの結果はHOLD。
    8. ReobservationBoundedContinuationProposalGateV0_1： 前段のexact受領書、導出された残余budget、必須の 新規観測・checkpoint・再entryを要求し、 observe_repository、inspect_artifact、 run_read_only_check、run_formal_verificationから 1件のみread-only次行為を提案。予約/実行/権限は付けない。
    9. ExternalGeneralBenchmarkSWEBenchVerifiedAdapterV0_1： 2026-07-21のさらに後段の外部評価用のprotocol-only。 gold patch・holdout labelsを候補生成・prompt・memoryへ逆流 させない。評価結果は自動で学習許可やGit権限にならない。

    この「学習」は版・作業単位に拘束された検証済み履歴の検索・ 次候補への再投入であり、モデル重みの更新ではない。 現行のsubtask memory関数はread-only lookupだけを実装し、 実GitHubへの永続保存・CodeAI次候補への無条件自動流入はしない。
