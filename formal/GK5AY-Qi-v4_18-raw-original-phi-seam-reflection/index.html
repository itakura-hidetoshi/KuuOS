    2. 数学的焦点：P93C.old raw-original と GK5AIの再帰φは異なる¶

    元F55の真正3-proof f について、選択P93Cのold生成元は元P89四セルの端点をP92B.original(f)／P92B.original(g)というrawな全体wrapperで受け取る。一方、GK5AIの真正構造写像φ(f)は元F55の全9構成子に対して再帰的に定義され、例えば元合成を選択側の合成へ、元恒等を選択側のreflへ写す。P92B.original f = φ(f) を定義的な等式として扱えない。

    実際、真正北四段C60長短経路にあるnativeGK5AINorthPentagonWithIdentity（元pentagon四段の後に元F55右恒等を合成した実在3-proof）について、

    P92B.original(nativeGK5AINorthPentagonWithIdentity)
  ≠ φ(nativeGK5AINorthPentagonWithIdentity)

    がrawな選択P92BのType値付き証明構成子の相違としてLean4で成立する。両者の間に4-cellが存在しないという主張はしていない。

    3. 本当に必要なseamは4-cell証明書（無条件存在ではない）¶

    独立GK5AYはNativeGK5AYOriginalPhiSeam first lastという真正依存型の条件付き証明書を定義する。各元F55 fごとに

    bridge(f) : P94A(P92B.original(f), φ(f))

    という選択P94A四セルのType値付き証拠を要求する。このレコードが無条件に inhabited だとは主張しない。Nonempty Seam iff 全元F55証拠に橋の真正P94A証拠が存在する、という正確なpointwise存在条件を証明した。

    これにより任意の実際のraw P93C証拠w : P93C(original(f),original(g))から、

    P94A(φ(f), φ(g)) :=
  symm(bridge(f)) ; P94A.old(w) ; bridge(g)

    を作る。等号で端点を置き換えるのではなく、本物の両端の高次比較を合成する。元P89証拠をP93C.oldへ埋め込む場合もこの区別を保つ。

    4. 真正元P89反射・局所obstruction・非単射性の正確な条件¶

    同じ元F54 route slotの元F55証拠f,gを固定し、raw P93C四セルwとseam証明書が実際に与えられる場合、

    GK5AQBadPair(f,g)
  ↔ ¬ Nonempty(OriginalP89FourCell(f,g))

    がLean4で成立する。選択P94A比較は本当のseamとwからすでに構成できるため、残る非反射障害は元P89証拠の欠損である。

    また、生のP93C比較がありながら元P89四セルが存在しない場合をRawP93Obstructionと厳密に定義する。raw P93C全面反射 iff RawP93Obstruction不存在は、seamの有無とは独立して成立する。seamと実在raw障害が両方与えられた場合だけ、元P89→P94A四セル商写像がある正確なF54 route slotで非単射になる。逆に元source class mapが単射でseamがあるなら、そのslotのraw P93C比較は元P89に反射する。元sourceの無条件faithfulness／nonfaithfulnessは未証明のまま保持する。

    さらに、P93C.oldが元P89四セルを本当に受け取っていても、そのrawP92B.original端点が再帰的φの像外であれば、GK5AUの内部source-holeは存在し得る。元4-cellがあることとrawな選択3-proofがφ像内にあることは別条件である。

    5. Qi v4.18：真正北C60への11宣言¶

    新規Qi Leanモジュールは、実際の北四段pentagon long/shortの元F54双Nat・Blocks・元F55証拠に以上を特殊化した：

    1. fivefoldGK5AYNorthSeam_nontrivial：北のraw証拠と再帰φの非同一性＋与えられたseam四セル。
    2. fivefoldGK5AYNorthRawP93ToStructural：真のraw P93C四セルをseam経由でφ端点P94Aへ移送。
    3. fivefoldGK5AYNorthRawP93_bad_iff_noP89：選択raw比較のBadPair iff 元P89欠損。
    4. fivefoldGK5AYNorthP89Old_both：真正元P89四セルとselected P94A四セルを併存させる。
    5. fivefoldGK5AYNorthRawObstruction_noninjective：与えられたraw障害とseamがF54 slotの非単射性を導く。
    6. fivefoldGK5AYNorthPhysicalSeamGate：4-cell seam条件と第五around Dart閉路・04／43物理向き・条件付き非単射性iffの併存。
    7. fivefoldGK5AYNorthPhysicalRawObstructionGate：raw障害が存在する場合のみの非単射と物理境界。
    8. fivefoldGK5AYNorthRawReflects_iff_noObstruction：全面raw反射 iff raw障害なし。
    9. fivefoldGK5AYNorthRawComparison_reflect_or_bad：seam＋実在raw比較なら元P89証拠またはGK5AQ BadPair。
    10. fivefoldGK5AYNorthRawReflects_of_allInjective：全F54 route slotの元class map単射を明示仮定した場合にraw P93C全面反射。
    11. fivefoldGK5AYNorthPhysicalRawReflection_of_allInjective：10の条件付き反射と第5Dart閉路・04/43方向・条件付き非単射性の整合性。

    物理的五行gauge frameはseam四セルや元P89証拠、source class map単射性を生成しない。

    6. Lean4エラーの根本原因と修正履歴¶

    独立GK5AY初回 Governance #41594170326 は、証明書フィールド名に予約語atを用いた構文解析失敗と、依存型forallのintro形式の問題があった。フィールド名をbridgeに改め、全依存型添字を保持した導入構文へ修正した結果、最終exact-source HEAD d61c1d6f...で全Lean検証成功。

    Qi v4.18初回 Governance #41604664430 は、have hreflect := ... が完全な∀依存型のraw反射命題を推論しきれず、経路添字の未解決メタ変数が残るという1件のtype mismatchを報告した。修正では

    have hreflect : nativeGK5AYRawP93Reflects
    fivefoldGK5AYNorthFirst fivefoldGK5AYNorthLast :=
  fivefoldGK5AYNorthRawReflects_of_allInjective data allInjective

    と明示し、定理仮定・結論・元定義は一切変更しなかった。最終source HEAD 98a743b0a777b8e8484e0d25722ce1f4c9b309aeで10,181/10,181 Strict Lean、30/30 Governance SUCCESS、11公理監査・sorryAxなし。

    7. 次：GK5AZ（仮称）¶

    選択P93C raw originalと再帰φの橋が必要なこと、実際のseamを条件として与えれば選択raw比較をφ端点へ移送できること、欠けた元P89 4-cellが厳密な障害となることが定まった。次は、証明書全体を無条件に仮定しない構成子別seam成立条件／局所obstruction、さらにGK5AXの元P89 vertical unit/assoc 3 family反射証明書とGK5AWの8種contextの合成整合性を精査する。実際のP92B.originalと再帰φの接続がどの構成子で直接構成でき、どこで新規高次証拠が必要かを分離する。無条件の全P94A normal form、元P89非単射性、Gray復元、無条件高次gluingは先取りしない。
