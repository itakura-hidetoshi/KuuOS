    1. 直接合成の単位正規形¶

    v4.79で、2つの真正FrontNormalの直接合成を、元ReassocRoute.transと、第二routeによる第一ScheduleのreassocSchedule移送・appendで構成した。

    今回、どの部分Family／状態F,sにも、真正Type値directNormalUnit(F,s) = ⟨ReassocRoute.refl F, Schedule.nil F s⟩を構成した。これは履歴商の形式的な単位ではなく、実在する元recutと元空Scheduleを保持する値である。

    frontPlanで解釈した単位は、元のrecut.reflを2回含むPlanになる。したがって元Planの構成子を単純に反射と等置せず、既存のplanObservedEq_left_reflから3観測に限った単位同値を導いた。

    directCompose_leftUnit_observed・directCompose_rightUnit_observedで、開始側および終了側の任意部分状態において、直接合成の左右単位を証明した。directCompose_*Unit_historyは、元のInterleavedHistoryのhistoryPlanと、正規化後の単位合成の全域観測一致を保持する。途中Step、元source Type値、最終部分状態を消去しない。

    2. 任意3連結の直接正規形と観測結合則¶

    任意の同一端点型で接続可能な三つの真正FrontNormal N₁ : F₀s₀ → F₁s₁、N₂ : F₁s₁ → F₂s₂、N₃ : F₂s₂ → F₃s₃について、

    • directAssocLeft N₁ N₂ N₃ := (N₁ ⋄ N₂) ⋄ N₃
    • directAssocRight N₁ N₂ N₃ := N₁ ⋄ (N₂ ⋄ N₃)

    を別々の真正Type値として構成する。directAssocLeft_routeとdirectAssocRight_routeは、それぞれ元の左／右括弧付けReassocRoute語を構成子どおり保存する。

    主定理directCompose_assoc_observedは、これらのfrontPlanが元PlanObservedEqで一致することを証明する。既存のv4.79直接合成観測則、v4.77のPlanObservedEqの合成合同性・結合則・対称性・推移律を順に組み合わせ、命題の弱化やcoverageの全単射性を導入しない。directCompose_observed_congrは各入力の観測同値に対する二変数合成の整合性である。

    主定理の観測は次をすべての適切な全域で含む。

    • 最終木の全raw添字iについて forwardIndex(left,i) = forwardIndex(right,i)。
    • 開始木の全raw添字jについて backwardIndex(left,j) = backwardIndex(right,j)。
    • 最終木の全真正source witnesswについて Pullback(left,w) = Pullback(right,w)。

    この真正source Type値等式をsubsingleton性で置き換えない。

    3. GK5CG五セル、経路・認証とobstruction境界¶

    • directCompose_assoc_rawSquareは証明済みforward一致に沿って、両括弧付けの元GK5CG五セル値のraw四セル端点を揃える。
    • directCompose_assoc_rawLoopは両側の元五セル値による実loopを構成するが、その自明性／非自明性、五セル等式、新規高次セルの存在は主張しない。
    • directCompose_assoc_pathとdirectCompose_assoc_certifiedは、両Planのsource pullbackが元Quiver.Pathおよび真正source認証付きP77部分Homを保存することを確認する。
    • directCompose_assoc_certify_rawは、最後の真正source値で各側を認証したraw比較が、その同じ側の選択済みraw比較と一致することを保持する。
    • directCompose_assoc_allCompatible_iff／directCompose_assoc_obstructed_iffは、各合成Planの全階層compatibility／否定が、同じ最終因子木tree F₃ s₃のcompatibility／obstructionにそれぞれ同値であることを証明する。

    終了状態s₃は完成状態に限定しない。元の全途中状態間でのobstruction不変、真正五セル値そのものの等式、loopの自明性、元route語の結合律・単位律の構成子的等式、higher coherenceは未証明として保持する。

    5. CI失敗とLean4 elaboration修正¶

    初回HEAD 1d02aa413e6da3f15f92a8992669b0703b883cabのCI #42166344525は、変更Leanファイル344行・354行のFunction expectedで失敗した。

    両方とも、directCompose_*Unit_history f g h k _ (.nil family s)と書いた匿名回帰例の余分なplaceholderが原因。実際の定理は履歴Hが唯一の追加明示引数であり、_がHを先に消費するため、後続の(.nil family s)を既に成立したProp証明項に関数適用する形に誤 elaborationした。

    修正は2例から余分な_を削除しただけ。変更Lean全文384行、依存importsとv4.77–v4.79の正確な定理引数、固定mathlib pin、実Leanエラーログ、公理出力を照合した。新規24定理・定義の文、仮定、結論、五セル履歴、source証拠は不変。初回CIは失敗のまま記録し、修正HEAD 31ee041ad0f94158dc23350bce5e67447bac9f1bで新しいexact-source CIを実行した。

    修正後CIは10,279／10,279 build success、実公理24／24は標準公理だけ、変更Lean warning/error 0/0、source/test-merge/squash Git tree完全一致。検証済みHEADを指定して定理PR #3183をsquashマージした。
