    1. 問題設定¶

    Qi v5.01では独立のUnitDiamondEightCellに一つのunitDiamond比較を加え、 旧法4整数観測量Sの降下は失われたが、第四整数Rの偶奇は新商へ降下した。

    残る課題は、同じraw六セル始終点の二つの七セル履歴で、 Rの偶奇が等しくても現行UnitDiamondEightCellで比較できない例の形式構成である。

    今回は新原始八セル・九セルを追加せず、現在の全型付き比較構成子に保存される 新たな整数観測量から不可能性を証明した。

    2. 13構成子上の整数単位則カウント¶

    sevenUnitStepCharge : SevenRewrite W long short c d → ℤを、 元の自由七セル証拠履歴Typeに対して構造再帰で定義する。

    • leftUnit、rightUnitの原始生成元に重み+1。
    • ほかの原始生成元assoc、inverseLeft、inverseRight、 doubleInverse、inverseId、inverseCompは0。
    • reflは0、symm Hでは符号反転、trans H Kと congrComp H Kでは加算、congrInv Hでは保存。
    U(H) = signed_count(leftUnit in H) + signed_count(rightUnit in H)

    重要なのは、旧v4.91 EightCellの22構成子すべてにおいて、 この整数値のまま等式が成り立つことである。 とくにzigzagDiamondは左経路に左単位則1回、 右経路に右単位則1回を含み、いずれもU=1となる。

    既存のTriangleEightCell、InvolutionEightCell、 InverseCompEightCell、IdentityEightCell、 UnitDiamondEightCellの追加生成元と全型付き文脈に対しても 帰納法で整数Uの保存を形式証明した。

    theorem unitDiamondEightCell_preservesUnitStepCharge
    (q : UnitDiamondEightCell W long short s t) :
    sevenUnitStepCharge s = sevenUnitStepCharge t

    この全構成子保存定理からQuotient.liftを用いて unitDiamondHistoryUnitCountを新商上の真の整数値観測量として構成した。

    3. 左右逆元消去とinverseIdの二因子前駆例¶

    w:Wの元のraw六セルに対し、次の左右別々の二経路を取る。

    sevenInverseUnitLeftDirect w  := .inverseLeft (.refl w)
sevenInverseUnitLeftVia w     := inverseId ; leftUnit
sevenInverseUnitRightDirect w := .inverseRight (.refl w)
sevenInverseUnitRightVia w    := inverseId ; rightUnit

    正確なLean定義ではcongrCompを通じた中間六セルと transを保持し、上の表記は適用順序の略記である。 左右を横合成してsevenBalancedInverseUnitFirst/Secondを得る。

    この二因子前駆例では、U=0対2、R mod 2=0対0であり、 既存のUnitDiamondEightCellでは比較不能と証明した。

    重要な訂正： 旧三整数のTは、第一経路が1、第二経路が0である。 inverseRightがT=1を持つためであり、 最初の同一視仮説は成立しない。Qi v5.02ではこれを sevenBalancedInverseUnit_tripleValuesとして明示的に証明した。

    4. 真正三角形critical pairによるTの相殺¶

    旧sevenLeftTriangleDirect(.refl w)(.refl w)と sevenLeftTriangleViaAssoc(.refl w)(.refl w)は、 元の型付き三角形critical pairである。 前者のTは0、後者のTは1となり、いずれもUは1である。

    これを二因子前駆例の左右の経路に逆向きに割り振って sevenBalancedUnitInvisibleFirst/Secondという 真正な三因子平行七セル履歴を作った。

                             H_first       H_second
元三整数 (T,J,K)          (1,0,0)        (1,0,0)
元第四整数 R mod 2        0              0
新整数U                   1              3
raw六セル始終点           完全一致

    全UnitDiamondEightCell比較でUが保存されるので、 もしUnitDiamondEightCell(H_first,H_second)が存在すれば 整数等式1=3が導かれて矛盾する。

    sevenBalancedUnitInvisible_noComparison
sevenBalancedUnitInvisible_distinctClasses
sevenTripleAndParity_notCompleteAfterUnitDiamond

    これらをLean4で形式証明した。元の三整数と残余偶奇の両方が等しくても、 現行選択八セル商では比較可能性を導けないという具体的な反例である。 全平行履歴の分類・大域thin性を主張するものではない。

    また二因子前駆例から、 sevenUnitStepCharge_notFactorThroughParityによって、 整数Uが残余偶奇の任意の非線形関数から普遍的に復元できないことも示した。

    5. 元P77 raw最終添字と厳密Eq境界¶

    pentagonActualBalancedInverseUnitWithSourceObstructionでは、 任意の元P77 raw最終添字に対し、 元pentagonAdjoinedSixCell_generatorを用いて 二因子前駆例の比較不能性と同じ偶奇を真正GK5CGのsource付き文脈へ輸送した。

    同時に¬ PentagonAdjoinedSixCellEqualityInterpreterを維持している。

    三整数も一致する強い三因子例は本Leanモジュールで任意のW上の 型付きraw七セル履歴として証明した。 その三因子例を元P77の真正六セルsourceとの追加横合成で輸送する定理は、 今回のP77定理とは区別する。新規source Eqを仮定していない。

    元F55/P77/GK5CG source、元七セル証拠履歴、旧高次商、 strict空と独立Kuu presentationのauthority境界は変更していない。

    6. Leanエラーの構造的原因と修正履歴¶

    初回PR HEAD 1d9871f3e2a78a8f9393e680720f21bedcdadd2bで sevenBalancedInverseUnit_sameTripleの未解決ゴールが出た。 調査で元TのinverseRight生成元の重み+1を再確認し、 誤った同一三整数主張を撤回して、 真正三角形critical pairによる明示的補償を加えた。

    2回目HEAD 82f18b171aae53e69909399b85198e8cfc7c48ecでは、 宣言用/-- ... -/コメントをendの直前に置いたため、 Lean4のパーサが後続宣言を期待する構文エラーが1件発生した。 これは定理失敗ではなくコメントの位置／種類の問題である。 通常コメント/- ... -/に置換し、 修正版HEAD f821aef132efeff078fb187785b0f01a39f42932で 全体のexact-source CIが成功した。

    元source・既存Lean定理・固定mathlib API・公開rootは一切変更していない。 過去のエラーを隠すsorryや新公理は導入していない。

    7. 未証明事項と次段階Qi v5.03¶

    今回も次を証明していない。

    • 任意の平行七セル履歴の比較可能性、全高次障害の完全分類
    • Uの一致から比較証拠が必ず存在するという十分性
    • 九セル以上のthin性、または元sourceのstrict Eqへの昇格
    • 強い三因子証拠の追加source文脈輸送（今回のP77定理は二因子前駆例）

    次のQi v5.03では、まずこの新たなU障害に対する局所合流を精査する。 新原始比較生成元が本当に必要な場合に限り別の独立presentationに 最小追加し、整数Uと残余偶奇の降下境界を再評価する。
