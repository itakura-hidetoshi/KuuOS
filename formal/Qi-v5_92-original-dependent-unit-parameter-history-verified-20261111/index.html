    2．元の依存型unitパラメータの観測¶

    SelectedV592OriginalUnitAtomは、同じ上位16D文脈のもとで

    Σ J : genuine raw17D endpoint,
  Σ N : genuine raw17D endpoint,
    SelectedLocalEighteen W l r J N

    という元の型付き証拠そのものを収納する。新しい19D比較や等号を構成しない。

    selectedV592OriginalUnitHistoryは、元の5構成子を直接再帰して、真正unitLeft before F G C after／unitRight before F G C afterの葉を元証拠・本来の17D始終端・付加パラメータごと順序付きリストに記録する。strictは空列、reverseは葉の元payloadを保持し、chainは左右リストを順序付き連結する。これはpayload-only履歴であり、反転の外側の位置やstrictの位置・raw括弧木は意図的に別の観測量へ残す。

    selectedV592OriginalUnitHistory_lengthは任意の元旧18D依存型証拠Mに対して

    History(M).length = OriginalUnitCount(M)

    を証明した。これはrestricted fragmentの定義にunitCountが一致するという条件付き主張ではない。

    3．2-unit往復閉路：履歴の一致は異fiberの等号ではない¶

    v5.91の真の元証拠U:J→Nから

    Forward(U)  = chain U (reverse U)  : J→J
Backward(U) = chain (reverse U) U  : N→N

    を元Typeのまま構成する。v5.92は両方向でHistory = History(U) ++ History(U)を証明し、元のunit数1なら歴史リスト長は双方2と証明した。

    ただし、元unitLeft・unitRightのJ≠Nはv5.91によって証明済みであり、この二つの閉路は異なる真正raw17D fiberに属する。歴史リストが等しくても、raw旧18D証拠の異fiber等号・比較居住性は得られない。

    4．同一真正fiberでの「履歴一致・括弧不一致」実例¶

    元unitLeftまたはunitRightの真正付加パラメータbefore/F/G/C/afterを固定し、その元証拠をU:J→N、真正往復閉路をR = chain U (reverse U):J→Jとする。実際の同一J→Jfiberで、

    A = chain (strict J) R : J→J
B = chain R (strict J) : J→J

    を構成する。元旧18Dのstrictは元unit数0、元unit payload履歴は空。そこでselectedV592ActualLeftTwoUnitSameFiberHistoryGapと独立の...Right...が次をそれぞれ証明する。

    History(A) = History(B)
Bracket(A) ≠ Bracket(B)
OriginalUnitCount(A) = 2
OriginalUnitCount(B) = 2
A ≠ B   (ACTUAL original typed old18D equality)

    括弧はそれぞれoldJoined oldStrict (oldJoined oldUnitLeft (oldReversed oldUnitLeft))とoldJoined (oldJoined oldUnitLeft (oldReversed oldUnitLeft)) oldStrict（右unitも対応）であり、元のchainへの結合律や単位律は追加していない。括弧が異なることを使って元raw証拠が異なると証明するため、履歴の非単射の実例だが、同じ内部括弧指紋の衝突ではない。

    5．Lean4エラー修正の型構造上の原因¶

    初回定理source 0acbf85b0a4551f894d7d108b4ef4ec3875f4ff2のCI #42907366988は、新規ファイルの6件のExpected type must not contain free variablesによりFAILURE。元の5構成子、v5.73内部括弧観測、v5.89 count、v5.91元往復閉路、新規Lean全文を照合した。

    発生理由は、l,r,before,F,G,C,after等の自由変数を式の内部に残したまま閉じた命題を判定するdecideを直接使ったこと。左／右の非等号各1件は、実際に定義計算で得られる閉じた非結合括弧木へchangeしてからdecideを使用。元unit数の等式各2件は実際の定義計算に従ってrflへ変更した。合計6箇所であり、定理の前提／結論、元のLeanファイル、固定Lean/mathlibは変更していない。修正後CIと公開CIは独立にSUCCESS。
