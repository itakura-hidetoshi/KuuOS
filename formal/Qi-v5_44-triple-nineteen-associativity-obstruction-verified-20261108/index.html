    2. 真正19D商の三変量観測¶

    Qi v5.43までのTrace・ActiveChain・ReverseCountは、既存の真正SelectedLocalNineteen比較5構成子それぞれで保存される。これらを組み合わせ、

    I₃(q) = ((length(Trace(q)), ActiveChain(q)), ReverseCount(q))

    をselectedNineteenTripleObservationとして同一の17D依存端点fiberの19D証拠商上に構成。selectedLocalNineteen_preservesTriple、selectedNineteenTriple_onClass、selectedNineteenTriple_eq_iffで保存・評価・成分の必要十分条件を証明した。元raw 18D Type値Eqとは同一視していない。

    3. 三変量を識別する具体的な型付きLR→RL transport¶

    入れ子Nat.pairと既存selectedMixedLengthCodeによりselectedMixedTripleCodeの単射性を証明。真正RL18D証拠から作る既存selectedMixedRightTracePowerを使い、source三変量を指数に符号化したselectedMixedTripleRawTransportを構成した。selectedMixedTripleBoundary.localTransportは元の真正Type値19D比較を入力とし、輸送先の真正strict比較を実際に返す。selectedMixedTripleAnchoredは指定LR証拠を元RL証拠へ輸送する比較を保持する。

    商降下の像の同一性について、この具体的境界に限り

    descend_triple(q₁) = descend_triple(q₂)
   ↔ I₃(q₁) = I₃(q₂)

    をselectedMixedTripleDescend_eq_iff_observationで証明した。v5.43では潰れていたreverse (reverse X)との差は、selectedMixedTripleDescend_separatesDoubleReverseで区別される。

    注意： これはsource側の三変量の一致を像の19D商クラスの一致と対応させる分類であって、sourceの三変量とtargetの三変量が全域で同じ値になるという主張ではない。

    4. 同一三変量を残す、真の括弧付け障害¶

    selectedContextEighteenLeftNestedCountは、生18D構文のchainで左側がさらにchainである箇所を数える。既存SelectedLocalNineteen5構成子すべての保存をselectedLocalNineteen_preservesLeftNestedCountで構造帰納法により証明し、selectedNineteenLeftNestedOnQuotientで真正19D商へ降下した。

    同一依存端点の真正生18D値Xに対し、

    L(X) = chain (chain X (reverse X)) X
R(X) = chain X (chain (reverse X) X)

    を構成。Trace(L)=Trace(R)とReverseCount(L)=ReverseCount(R)は任意Xで成立する。外側traceが非空ならActiveChain(L)=ActiveChain(R)も成立する。一方LeftNestedCount(L)=LeftNestedCount(R)+1が常に成立し、元19D商では[L]₁₉ ≠ [R]₁₉、既存SelectedLocalNineteen Type値比較も非存在と証明。

    真正LR二重文脈証拠のtraceは非空なので、この実例を元のLR 19D fiberで構成できる。selectedMixedTripleDescend_notInjectiveとselectedMixedTripleBoundary_noReflectionは、今回実装した三変量境界が非単射で、完全19D比較反映を持たないことを証明。selectedMixedTripleAnchored_chosenSwapは指定点でのcoarse swap観測一致のみ認証する。

    5. 初回CI失敗と修正理由¶

    初回と再検証では、依存endpointの変わるSelectedContextualEighteen再帰をsection固定添字のまま扱ったことに由来するelaboration failure、および一般simpの展開・正値条件を指定しないためのActiveChain算術証明の失敗があった。再帰不変量を端点多相の明示的定義にし、算術を局所的なchange・正値条件・omegaに変更した。元のType値・仮定・旧定理には手を加えず、最終HEADのStrict LeanがSUCCESSとなった。エラーをsorryや追加公理で回避していない。
