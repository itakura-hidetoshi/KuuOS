# VerifyOS public receipt v0.11

Append-only extension of v0.10. A trusted issuer reads a sealed anchored snapshot, recomputes the prior v0.8 publication with its private host MAC key, and checks agreement with the independently reconstructed public projection before signing. OpenSSL Ed25519 signs a domain-separated canonical payload; no new cryptographic primitive is implemented. The signing key must be independently provisioned, held outside the model and never committed. The raw 32-byte public key is supplied independently to the verifier, not trusted merely because it is mentioned in a packet. A trusted OpenSSL executable and environment are prerequisites.

The public verifier needs only the packet, original seed and revision log, raw execution bundle, independently expected current request/context, sealed anchor tip and public key. It verifies the actual signature, replays v0.7/v0.8, reconstructs the v0.9 row and sealed v0.10 PREPARE/SEAL digests, verifies the receipt structure, reprojects all required claims and branches, and checks exact signed payload equality. It uses neither the private signing key nor the host MAC key nor a database. The entire original family, conditional exclusions and unresolved claims stay represented via the replay digest and branch/claim rows; a signed partial answer remains partial. Missing or mismatching data, an old receipt against a newer expected anchor, invalid signatures, and even a valid signature on an incorrect projection are HOLD. The signature binds the attestation to a key, not a human identity or the fact that an external executor ran the claimed command. The verifier relies on the independently trusted signer for actual execution provenance, host isolation, and correct original anchor/context capture. `PUBLIC_SIGNATURE_AND_REPLAY_MATCHED_ONLY` is separate from `answer_status` and never upgrades the latter. The same signed snapshot can be verified repeatedly. No freshness at delivery, external independent execution attestation, proof/action authority, arbitrary-language completeness, third-party identity, global replay prevention, or ChatGPT interception is claimed.

The receipt and replay material are private by default and may contain sensitive user data and execution paths. Sharing them requires a separate authorized decision. Tests use ephemeral Ed25519 keys, synthetic gate scripts and real subprocesses/SQLite transactions; the public verifier is also exercised in a separate spawned process without the private signing key or host MAC key. No secret, real user question, private ledger or live receipt is committed. All preceding source and Lean files remain unchanged.
