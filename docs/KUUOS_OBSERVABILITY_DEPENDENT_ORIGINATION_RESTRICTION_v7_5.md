# KuuOS Observability Dependent-Origination Restriction v7.5

## Purpose

v7.5 continues the observability work as **dependent origination**, not as a graph.

v7.4 established:

```text
presentations
  -> conditioning families
  -> generated presentation relation
  -> local compatibility
  -> descent / held descent / obstruction
```

v7.5 asks the next local-to-global question:

> When a presentation sector is restricted back to each generating condition, does local compatibility survive?

This lets KuuOS distinguish a simple local obstruction from a genuinely higher gluing obstruction.

## Restriction

A v7.4 sector may be generated by several conditioning families.

Example:

```text
condition family C1 presents {A, B}
condition family C2 presents {B, C}

generated presentation class = {A, B, C}
```

v7.5 restricts the sector to each family separately:

```text
{A, B, C}|C1 = {A, B}
{A, B, C}|C2 = {B, C}
```

and rechecks the bounded local comparisons already preserved by v7.4.

No new provider call is made.

No raw log is needed.

## Local restriction states

### restriction_compatible

Every comparison inside the restricted conditioning family is:

```text
overlap
or
within_tolerance
```

with `temporally_compatible = true`.

### restriction_held

At least one required local comparison is unresolved because of:

```text
insufficient_time_metadata
source_obstruction
missing_pair_presentation
```

### restriction_obstructed

At least one comparison inside the conditioning family is explicitly:

```text
disjoint
```

### restriction_trivial

The restriction contains fewer than two presentations.

This is not an error.

## Generator-local obstruction

Suppose one generating family is already inconsistent:

```text
C1 = {A, B}
A/B = disjoint
```

Then the obstruction is already visible locally.

v7.5 classifies the sector as:

```text
generator_local_obstruction
```

There is no need to invoke a higher gluing explanation.

## Higher gluing obstruction

The more interesting case is:

```text
C1 = {A, B}  compatible
C2 = {B, C}  compatible

but

A/C = disjoint
```

Then every generating condition is locally well behaved, yet the equivalence closure generated by the conditions does not admit a coherent descent.

v7.5 records:

```text
higher_gluing_obstruction
```

This is not a graph-connectivity failure.

The presentations are related perfectly well.

The failure is that **locally compatible conditioned presentations cannot be glued into one presentation-independent sector without contradiction**.

That is the important KuuOS dependent-origination distinction.

## Higher gluing unresolved

A similar nonnegative state exists when:

```text
C1 local restriction = compatible
C2 local restriction = compatible

but A/C semantics are unavailable
```

Then v7.5 returns:

```text
higher_gluing_unresolved
```

rather than inventing either compatibility or obstruction.

The current formal frontier includes:

where restriction of localized 2-cells is proved to commute with left and right bicategorical whiskering.

v7.5 is **not** that theorem instantiated in Python.

The runtime only checks a finite, bounded shadow:

```text
conditioning-family restriction
  ->
local bounded semantic compatibility
```

Accordingly the packet fixes:

```text
restriction_preservation_is_formal_v4_61_theorem_claim = false
higher_coherence_claimed = false
formal_v4_61_restriction_whiskering_replaced = false

```

Lean remains theorem authority.

## Why this belongs to dependent origination

The structure is:

```text
presentation A
presentation B
presentation C

condition C1: A and B arise in one exact contextual relation
condition C2: B and C arise in another exact contextual relation

restriction to C1 -> compatible
restriction to C2 -> compatible

generated presentation class -> may still fail descent
```

No entity is treated as an intrinsic object.

The meaningful question is whether conditioned local presentations can descend coherently.

This preserves:

```text
condition != substance
presentation != substance
descent class != substance
local compatibility != global compatibility
relation != causal direction
runtime check != theorem proof
```

## Runtime chain after v7.5

```text
v7.0 bounded re-observation
  ->

  ->

  ->

  ->

  ->

       |

```

This is now a genuine local-to-global dependent-origination pipeline rather than an observability graph.

## Validation

The focused checker covers:

1. a successfully descended sector whose every conditioning-family restriction remains compatible;
2. a generator-local obstruction;
3. a higher gluing obstruction where all generators are locally compatible;
4. a higher gluing unresolved case;
5. a locally unresolved restriction;
6. an isolated local presentation;
7. stale source-digest rejection.

No Lean theorem files are modified, so Strict Lean is intentionally not invoked by the focused runtime validation.

## Next direction

The next dependent-origination step is not to draw the sectors as a graph.

It is to introduce a bounded **higher compatibility witness** for overlapping conditioning families:

```text
restriction to C1
restriction to C2
agreement on their common presentation
higher compatibility witness
```

and then test whether such witnesses are enough to remove the higher gluing obstruction in finite runtime sectors.

That would approach the formal 2-cell/coherence frontier while keeping the theorem boundary explicit.
