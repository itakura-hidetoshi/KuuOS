# 空OSをGPT-6で使う

このパッケージは、空OSの四原則・思考ルート・関係と履歴の扱いを、新しいモデルへ明示的に渡すための入口です。GPT-6向けの利用手順を含み、基本の起動文はモデルに依存しません。

## すぐ使う

1. [BOOTSTRAP_JA.md](BOOTSTRAP_JA.md)を開き、全文を新しい会話に貼り付けるか添付する。
2. 「この文書の空OSを適用して、○○を進めて」と依頼する。
3. 継続中の仕事がある場合だけ、[HANDOFF_TEMPLATE.json](HANDOFF_TEMPLATE.json)の項目に沿って、目的・直前の判断・未解決点・出典・許可の範囲を一緒に渡す。JSONを編集できない場合は、同じ項目を普通の文章で書いてもよい。

URLから読ませる場合は、使いたい版のコミットをGitHubのパーマリンクで固定し、取得できない場合は本文を貼り付ける。「リンクを渡した」だけで読み込み済みとは扱わない。通常の起動に全リポジトリや全Leanファイルの読み込みは不要で、専門作業の資料は必要なときに追加する。

読んだ相手は、例えば「起動文の基本原則を適用しました。以前の対話履歴はまだ受け取っていません。今回の依頼を進めます」と短く応答できる。これは読み込み確認であり、モデル性能や履歴の完全継承を証明する判定ではない。

## ファイル

| ファイル | 用途 |
|---|---|
| [BOOTSTRAP_JA.md](BOOTSTRAP_JA.md) | 単独で貼り付けられる日本語の起動文 |
| [HANDOFF_TEMPLATE.json](HANDOFF_TEMPLATE.json) | 意味の原則と個別の対話履歴を分ける空の継続用テンプレート |
| [INHERITANCE_TESTS.json](INHERITANCE_TESTS.json) | 16件の行動テストと判定基準 |
| [EVALUATION_TEMPLATE.json](EVALUATION_TEMPLATE.json) | 未実施から始める評価記録 |
| [SOURCE_MANIFEST.json](SOURCE_MANIFEST.json) | 参照した正本のコミットとファイル、モデル資料 |
| [VALIDATION.md](VALIDATION.md) | 検証範囲と再現方法 |

この文書群は対話用の移植仕様であり、既存runtimeに接続する実行アダプターではない。公開テンプレートには実際の患者情報、私的な対話、認証情報を入れない。個別履歴は利用者が指定した適切な保存先で扱う。

## GPT-6への適応

OpenAI公式の[Model guidance](https://developers.openai.com/api/docs/guides/latest-model)を2026-09-08に確認した。記載された対象はGPT-6 Astra、APIモデルIDは `gpt-6-astra`。個別アカウントやChatGPTの選択画面での利用可否は、このリポジトリからは確認・変更しない。

起動文には、依頼済みの仕事を最後まで進めること、必要な確認だけを行うこと、指示ファイルの位置づけ、簡潔な日本語で返すことを明記した。設定よりも実際の行動を[継承テスト](INHERITANCE_TESTS.json)で確認する。

既存のAPI利用者が接続するときの設定メモ：

| 項目 | 公式資料に基づく扱い |
|---|---|
| モデル | `gpt-6-astra` |
| ツール利用 | Responses APIを使用する |
| reasoning | `none`・`minimal`からの移行は`low`を起点に比較する。それ以外は現在有効な設定をまず保つ |
| sampling | `temperature`・`top_p`・`top_logprobs`を送らない |
| logprobs | Chat Completionsの`logprobs`、Responsesの`include`内の`message.output_text.logprobs`を除く |
| 履歴・権限 | アプリ側で確認・保持する。プロンプトだけで転送済みとは扱わない |

この追加ではAPIを呼び出さず、モデルの自動切替・認証設定変更・外部メモリ更新を行わない。API仕様は更新されうるため、実装時に公式資料を再確認する。

## 何を継承するか

| 層 | 継承するもの | 確認方法 |
|---|---|---|
| 意味 | 空・縁起・二諦・中道、局所と全体、複数表現、条件付きの有効性 | 原則の復唱に加え、未知の事例への適用 |
| 関係・履歴 | 利用者の目的、訂正、決定理由、却下理由、未完了の仕事 | 出典のある継続情報と、訂正・再開テスト |
| 実務 | 依頼の範囲、完了条件、利用可能なツール、実際にある許可 | 許可された行為の実行と結果の再観測 |
| 検証上の地位 | 正本、実験枝、実行済みチェック、未検証部分 | exact commitと対象を明示した証拠 |

自然な言い回しの再現や基本原則への賛同だけでは、関係・履歴の継承や安定した適用を示さない。

## 継承手順

1. **出発点を固定する。** 使用した起動文のコミット、原則の参照コミット、評価ケースの版を記録する。未取得の私的な文書や別パケットを採用済みにしない。
2. **会話に読み込む。** 四原則と必要な個別履歴を渡す。欠けている情報はnull・空欄・未取得のままにする。モデル名は画面・API等で確認できたものだけ記録する。
3. **仕事を進める。** 既に許可された範囲の有用な作業は継続する。新しい権限が必要な部分は切り分ける。評価待ちを理由に通常の対話を全面停止しない。
4. **行動を評価する。** 下記の比較条件で回答・実行証拠を保存し、意味と履歴を別々に評価する。
5. **訂正し、再観測する。** 失敗例、修正した起動文の版、再試験結果を残す。出力の流暢さや自己申告では合格にしない。
6. **継続情報を更新する。** 次の会話へ渡す要約を作成し、参照元・変更理由・未解決事項を保つ。保存や外部への適用は利用者の指示と実際の権限の範囲で行う。

## 再現可能な比較

モデル、利用可能なツール、reasoning設定、課題、提供情報、評価基準をそろえて、次の条件を別の会話で実行する。利用できない条件は「未実施」と記録する。

| 条件 | 渡す情報 | 観測すること |
|---|---|---|
| cold | 同じ課題と事実。空OS起動文は付けない | 起動前の比較基準 |
| bootstrap | 同じ課題と事実＋起動文 | 意味・判断の保持 |
| bootstrap_with_handoff | 同じ事実を履歴テンプレートでも整理＋起動文 | 訂正、理由、作業再開の保持 |
| retention | 上記の後に10往復以上の別課題を挟む。起動文を再掲せず対応する別事例を出す | 同一会話内での保持 |
| reentry | 新しい会話へ起動文と継続情報を再投入する | 明示的な読み込みによる再開 |

過去の事実が必要なケースでは、coldにも同じ事実を通常文として与える。履歴情報そのものの追加効果と、空OSの起動文の効果を混同しない。全ケースと期待条件は評価者用で、被評価モデルへはそのケースの課題・与件・turnsだけを渡す。採点表や望ましい答えは渡さない。PB16は同じ会話でturnsを順番に出し、未提示の後続turnを先に読ませない。

各条件を独立した新規会話で3回以上試す。記録にはモデル表示、日時、設定、入力版、各応答または保管先、実行の成否、評価者と判定理由を残す。出力を作ったモデルの自己採点だけで受入判定しない。別評価者または利用者が出力と証拠を確認する。モデルが不明ならunknownとし、GPT-6実測結果とは呼ばない。

ケースごとの0/1/2評価から、意味と履歴の二つのスコアを別々に計算する：

`score = その区分の得点合計 / (2 × その区分の全ケース数)`

未実施・未採点が一件でもある区分はスコアをnullにし、合格扱いにしない。critical_failureに該当したケースがあれば、平均点で埋め合わせず、その版を修正して再試験する。目安は両区分とも0.85以上、critical failureゼロ、全ケース実施。これは本パッケージの暫定的な運用基準であり、統計的優位性や普遍的な同等性の保証ではない。

語句の一致を採点しない。用語がなくても、条件の違いを扱い、履歴を保ち、仕事を適切に進めれば評価する。用語を並べても、未検証の事実を断定し、矛盾を消し、必要以上に停止すれば低評価となる。coldとの差は改善・悪化の観測として残し、初めから改善があると仮定しない。

## Source Lockと更新可能性

Source Lockは「この試験・この説明でどの版を使ったか」の固定であり、古い内容を永遠の正本にする規則ではない。新しい証拠やユーザーの訂正を得たら別の継続情報・版として記録し、差分を評価する。試験中の入力を黙って差し替えない。運用上必要な更新と、比較実験の固定条件を区別する。

正本と検証枝が異なる場合、検証枝の成功はそのexact commitと検証範囲に結びつける。正本の地位を自動更新しない。KuuOSのPR #1558はREADMEに記載されたvalidation-onlyのstacked Draft PRであり、merge・Ready化・auto-mergeの対象にしない。本パッケージはその枝を取り込まない。

## 戻す範囲

起動文や継続情報に問題があれば、それらの適用版・解釈・推奨設定を前の版へ戻せる。旧モデルが利用できない場合でも、以前のパケットは保存できる。

既に送信したメール、外部への書き込み、データ削除、学習済み重み、基盤モデル自体まで巻き戻ったと説明してはいけない。外部作用は実際の状態を再観測し、必要なら別の復旧作業として扱う。履歴は消去せず、訂正を追記する。

## 適用と採用の地位

`loaded`は起動文を読んだこと、`evaluated`は記録されたテストを行ったことを表す。いずれも正本への採用、MemoryOSの上書き、恒常的な内部変化、転依、実行権限の付与を意味しない。

この追加文書は、別の「KuuOS Model Migration Protocol」や事前検証報告の採用状態を変更しない。未提供のレポートの合格件数を、このパッケージの実測結果として転記しない。
