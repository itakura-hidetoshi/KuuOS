# VerifyOS question translation v0.5

Append-only extension of v0.4. The host captures the original UTF-8 bytes, not a model paraphrase. The bounded parser accepts the five prior exact questions, the prior canonical typed JSON, or a Japanese sentence consisting of one registered prefix, one or more distinct registered clauses separated by `、`, a registered request suffix, and an optional exact freshness condition. The vocabulary and policy are in the runtime. A current-state prefix or freshness condition always adds `current_state`; neither can be discarded. Each consumed span has byte offsets, SHA256 and mapped topics. Unknown, negated, duplicated or restricted clauses are retained as unresolved spans and cause HOLD; unrecognized sentence structure retains the entire original as an unresolved span. No fuzzy match, whitespace normalization, free-text semantic entailment or language-model classification is admitted.

`compile` emits a translation candidate with a v0.4 typed question and contract, not verified evidence. `check` compares the supplied candidate bytes against the independently derived canonical typed question; no missing or extra topic is accepted. `issue` checks both the translation and original-question context before invoking v0.2's execution/admission path; it creates a new private evidence directory exclusively, never overwrites it. A successful issue is admission only, not publication. Publication recomputes the translation, checks original question digest against the admitted context, and uses the v0.3 claim projector with the required plan derived from v0.4. It does not substitute the typed bytes for the original question in the context. Display recomputes the complete packet. Required claims remain HOLD even if request, context or evidence files are missing, where the original contract can still be compiled.

The trusted host owns original question capture, the candidate, immutable snapshot, anchors, context, key, and controlled output channel. It must actually use the v0.5 issue route to enforce preflight before execution. Publication of an older v0.2 admission does not certify that preflight preceded that historical execution. No unrestricted natural-language equivalence or semantic completeness, external truth, freshness, Lean proof, action permission, or ChatGPT integration is certified. The 504-case finite test covers the 63 nonempty clause subsets in registered clause order, both prefixes, both suffixes and presence/absence of the freshness condition; it is not a proof for arbitrary permutations or unrestricted language. Synthetic pinned gate scripts are executed as subprocesses. No private inputs, live anchors, secrets or actual ledger receipts are committed. Prior sources are unchanged.
