# VerifyOS JSON projection v0.16 — research candidate

This additive research probe starts from the independently checked v0.15 R2 source. It connects actual JSON receipt bytes to the typed projection rather than generating predecoded Lean value literals. The original v0.3 field inventory is reproduced as fixed Lean paths, including nested stdout review fields and process exit codes. The raw outer receipt and both raw stdout strings are parsed in Lean. Object member uniqueness is checked before construction of a tree map. The parser uses the pinned Lean core Parsec primitives and bounded recursion; Unicode-escape spelling (including the conservative backslash-u precheck), decimal/exponent tokens, excessively long integers, excessive input size or nesting/member fuel are outside this profile and HOLD. It supports ordinary JSON whitespace, unsorted object fields, literal Unicode and short escapes, subject to those bounds. It is not a general JSON decoder. No normalization of fractional/exponent tokens into natural numbers is admitted. The host checks UTF-8 before Lean invocation.

The relational theorems establish typed conversion from the decoded JSON AST, exact field provenance for a projected value, context binding, missing-field HOLD, unique insertion and preservation of original required identifiers. They apply the actual v0.15 observed/Forced equivalence and do not prove general parser correctness, full Python refinement, or the truth of admission flags. SHA256, signature verification and admission remain separately trusted host checks, not theorems of this module. In particular, the context hash is obtained from the independently verified signed publication; it is not a claim that the raw v0.1 bundle itself carries the question context. The Lean CLI is a diagnostic projection tool, not an authority or a publication API. Its exit zero means the batch returned results, which can be HOLD or partially observed.

The runner creates an actual admitted synthetic v0.13 signed pair, checks the bound raw-bundle digest and context, and passes the original JSON bytes into Lean. It compares the exact ordered 18 value rows against the existing v0.3 projection and signed rows. Additional mutation cases intentionally do not possess valid admission; they exercise the lower-level conversion under simulated inputs, including duplicated keys, numeric type confusion, malformed JSON, altered fields, context mismatch and unsupported-field injection. All generated data is synthetic and no real user question, private ledger, receipt, key or credential is committed. The CI artifact contains only synthetic cases and diagnostic outputs. The independently gated runner regenerates a fresh synthetic pair and must also replay the first runner's exact input bytes and compare the entire output. The raw input hashes, source hashes and separate receipts are retained. These are acceptance conditions, not preclaimed results.

The probe imports core Lean plus the two prior research modules; it does not change prior declarations, import mathlib, or register a public proof root. No new axiom or sorry is permitted. Direct Lean audits named declarations, actual Lean MCP audits the 17 general theorems, and independent CI is allowed only after the complete sandbox succeeds. Cryptographic implementation soundness, arbitrary-language semantics, actual execution provenance beyond the inherited verification conditions, publication authority, current state and action authority remain outside this result.
