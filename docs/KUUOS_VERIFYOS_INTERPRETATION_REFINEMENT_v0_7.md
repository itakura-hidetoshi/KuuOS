# VerifyOS interpretation refinement v0.7

Append-only extension of v0.6. The trusted host retains the original family and captures explicit user confirmations of registered ambiguous spans. Each confirmation narrows the active view by an exact choice index; it does not refute the excluded interpretation or certify the user's general intent. Evidence availability, model preference and asserted identity are not confirmation. All original branches, their claims and exclusions remain in the publication.

The host independently retains the exact canonical confirmation log and its expected SHA256. `empty_log(family, context)` constructs the initial envelope. Each event has schema `kuuos.verifyos.interpretation-refinement.v0.7.confirmation`, one-based sequence, parent_sha256 (genesis for the first event, preceding canonical event digest otherwise), unique 64-hex event_id, source `host_captured_explicit_user_confirmation`, span_index into the original trace, exact span_sha256 and choice_index. A trusted host supplies these from an actual explicit choice; a self-declared source label does not authenticate a human. The log schema is `kuuos.verifyos.interpretation-refinement.v0.7.log`. Genesis binds original family and context. The expected log digest must be obtained independently of the candidate, not recomputed from an untrusted log. The host is responsible for append-only storage, atomic updates and a separate confirmation capture channel. The module is a read-only replay/egress checker, not that storage or UI. It does not verify external identities or cryptographic nonrepudiation.

`replay` verifies the original question, family and context, exact anchored log, parent links, event IDs, spans and registered choices. Every removed branch retains its first exclusion event digest and reason. A repeated or conflicting confirmation is HOLD, with the valid prefix and rejected event retained. Corrections require a separately bound new context; no undo or overwrite is supplied. The original family stays intact; active common and union requirements are recomputed from the surviving branches. `publish` recomputes v0.6 evidence for the entire original family and marks active branches; it does not discard original HOLD claims. `display` recomputes the entire authenticated packet. Exit 0 for publication means only ACTIVE_VIEW_ALL_OBSERVED for one remaining registered interpretation; the original family status can still be ambiguous or partial. Replay exit 0 is only a structural check. Missing or invalid evidence/logs produce HOLD. No automatic selection or proof/action authority is granted. The trusted host must isolate its keys, anchors, original question, runtime and verification output. No global semantic completeness, actual human identity, external freshness, external evidence authenticity, Lean theorem or ChatGPT interception is certified. Synthetic tests use real child processes; no private logs, keys or ledger are committed. Previous modules and Lean source remain unchanged.
