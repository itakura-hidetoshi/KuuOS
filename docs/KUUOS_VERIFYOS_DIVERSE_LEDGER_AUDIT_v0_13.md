# VerifyOS diverse ledger audit v0.13

Append-only continuation of v0.12. Two separately signed runs of the same gate may share a defect. `audit` reads a third host-selected immutable snapshot against the independently supplied full inventory and request pins, using a separate standard-library implementation. It imports neither inherited gate code nor the v0.1 runner, and invokes no gate subprocess. It reconstructs the integrity and scope summaries, including each review disposition, from original registry/event bytes. `verify_diverse` first checks v0.12's signed pair, then compares both full parsed JSON outputs with the reconstruction. No majority rule overrides a disagreement. Both signed projections, independent result and field evidence remain available in HOLD. The original answer status, including ambiguity and unsupported claims, is preserved only for a matched profile.

The supported profile is intentionally bounded: pinned base inventory with ten unique rules, sequence 0 through 128, no new rules, withdrawals, research certificates or notification intents; observational main/research head transitions only. All supported records are bound to their bytes, prior digest, pins and trusted tip. A rule's scope, provenance binding, exclusion and premise checks are recomputed against the frozen registry. Exact canonical JSON comparison for PASS checks is stricter than Python equality (e.g. true is not 1). Unsupported transitions or incomplete inputs HOLD. This is a second implementation of selected structural obligations, not a proof of equivalence to the complete v16/v16.1 gates; base content and external evidence truth remain dependent on independent trusted pins. Independent organization, method correctness, runtime isolation, proof/action authority, current-at-delivery freshness and ChatGPT interception are not certified. The shared Python runtime and shared specification can themselves have common defects. No arbitrary code execution, remote service or private data is added.

Tests construct synthetic fixed-registry ledgers, invoke real child gates and sign with two ephemeral Ed25519 keys. In the common-mode falsification test both gate implementations report rule_count=11 from a ten-rule registry; v0.12 agrees, but v0.13 recomputes 10 and HOLDs. A separate private acquired-snapshot test is not committed. No preceding source or Lean file changes.
